# Единая офлайн-библиотека календарных икон (WebP)

## Безопасная привязка

Источник истины — CalendarFeast с идентификаторами id, sync_uid, source_id.
Не меняем CalendarDay.main_feast, CalendarDay.feasts, жития, тропари,
кондаки и даты. Совпадения только по заголовку запрещены.

## 1. Инвентаризация (только чтение)

Из папки molitvoslov-backend:

    python manage.py audit_calendar_icons --inventory reports/calendar-icons.csv

Экспорт включает все памяти, текущие URL, идентификаторы, число связанных
дней и пустые поля для согласованной замены. CSV открывается в Excel.

## 2. Одна икона 480×640 WebP, без обрезки

Требуется вручную проверенный JPG, PNG или WebP, желательно с исходным
разрешением не менее 800×1100. **В APK включается только одна копия каждой
уникальной иконы: 480×640 WebP, качество 80**. Оригинал остаётся вне APK,
его не нужно дублировать в мобильной сборке.

    python -m pip install "Pillow>=10,<13"
    python -m api.calendar_icon_variants --source "C:\icons\original.png" --out "C:\icons\ready" --asset-id "sync_uid_праздника"

Икона вписывается целиком (contain), без обрезки и искусственного
увеличения; поля нейтральные. JSON сохраняет SHA256 оригинала и
реальный размер результата в байтах для оценки APK.

Точный размер всей библиотеки определяется после конвертации:
общий размер встроенных WebP практически полностью добавляется к APK,
так как WebP уже сжат. **Не храните мастер-копии рядом с APK-ассетами.**
Для Telegram возможен публичный адрес того же файла, но мобильному
приложению интернет для показа подготовленных икон не требуется.

## 3. Проверяем изображения, источники и лицензии

В CSV заполните new_icon_url, image_width, image_height,
source_page, image_credit, usage_rights. Только после визуальной проверки
соответствия святому и прав на фотографию установите:
subject_verified=yes, rights_verified=yes, approved=yes.

Проверка без изменений базы:

    python manage.py audit_calendar_icons --manifest reports/calendar-icons.csv

Применение ТОЛЬКО к локальной SQLite, с резервной копией и одной транзакцией:

    python manage.py audit_calendar_icons --manifest reports/calendar-icons.csv --apply

Каждая строка повторно проверяется по id, sync_uid, source_id, title
и ожидаемому старому URL. Любой конфликт отменяет работу. Обновляются
только icon_url и updated_at, остальные поля и связи сохраняются.
Массовая замена без проверки не предусмотрена.

## 4. Включение новых икон в полностью офлайновое приложение

После проверки выбранных изображений обновите ссылки в локальной
Django SQLite. Для офлайна **не требуется Supabase**: календарный JSON
и изображения должны быть сформированы из этой локальной базы.
У текущего Android-приложения офлайн-календарь генерируется отдельно,
и загруженные/встроенные данные должны содержать привязку по
sync_uid, source_id или URL. Версию генератора надо применять вместе
с обновлённым сериализатором (он теперь передаёт sync_uid).

Далее перегенерируйте calendar JSON и выполните
.github/scripts/build_calendar_offline_bundle.py, затем пересоберите APK.
Скрипт теперь собирает **все памяти**, найденные в календарном JSON
(главные и дополнительные), дедуплицирует одинаковые URL и создаёт
один WebP 480×640 на уникальную икону.

Мобильный интерфейс сначала показывает встроенную иконку по UID /
source_id / URL, и только если её ещё нет в APK — обращается к
сохранённому удалённому URL. Чтобы добиться 100% офлайна, нужно
устранить все отсутствующие иконки на этапе аудита и проверить, что
количество fallback-запросов равно нулю. Не нужно хранить мастер,
display и offline версии одновременно.

Сейчас исходный генератор использует calendar_2026.json. Для полного
офлайн-охвата 2025–2027 следует дополнительно собрать все годы,
не полагаться только на сборку для 2026 года.

Для автономного Telegram-бота — отдельная SQLite-копия, которую
можно экспортировать из той же локальной базы. Иконки Telegram могут
быть опубликованы по HTTPS для предпросмотра, но приложение от этого
не зависит. Слои icon_overrides.json Telegram не меняют Android APK.

## Ограничения

Нельзя получить тысячи заведомо правильных и правомерно используемых
икон простым поиском: возможны одноимённые святые, различные изображения
соборов, даты и варианты икон. Пока новый образ не подтверждён,
существующая привязка сохраняется. Ветка содержит инструменты, а не
выполненную массовую замену реальных икон.
