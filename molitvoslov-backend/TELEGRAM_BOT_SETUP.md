# Православный Telegram-бот (на базе "Молитвослова")

Бот использует **существующую Django/SQL базу**: календарь, полный синодальный текст Библии, жития, иконы, тропари и кондаки. Он не обращается к ИИ и ничего не придумывает.

## Возможности

- /start и /help — список команд.
- /today — чтения текущего дня: полный текст Евангелия и Апостола, стих из Книги Притчей, житие/история праздника, тропарь, кондак и икона.
- /all — те же материалы плюс все дополнительные календарные чтения (праздничные, святых).
- /date YYYY-MM-DD — публикация за указанную дату.
- /id — свой chat_id для рассылки.

Обычный режим берёт первое чтение каждого вида по полю order, а /all возвращает все. При отсутствии библейского диапазона бот **сообщает об ошибке**, а не подставляет выдуманный текст. Длинные тексты делятся на несколько сообщений. Житие и икона — от основной календарной памяти.

Цитата выбирается **только из Книги Притчей Соломоновых**, из существующих 917 стихов синодального перевода. Технический фильтр исключает очевидные обрывки, после чего идёт фиксированная годовая ротация. Для идеальной редакционной подборки из 365 наставлений потребуется отдельная ручная проверка.

## Как запустить

1. Создайте бота через [@BotFather](https://t.me/BotFather), отправив команду /newbot. Токен не публикуйте и **не добавляйте в GitHub**.
2. Подготовьте стандартный Python/Django backend (venv и requirements.txt). Он должен быть подключён к **заполненной** БД "Молитвослова" (локальная SQLite либо настроенная Supabase PostgreSQL). Используются уже существующие переменные SUPABASE_DB_HOST, SUPABASE_DB_USER, SUPABASE_DB_PASSWORD, SUPABASE_DB_PORT и др.
3. В PowerShell:

   $env:TELEGRAM_BOT_TOKEN = "<секретный токен BotFather>"
   cd C:\m\repo\molitvoslov-backend
   .\venv\Scripts\python.exe manage.py telegram_bot

   Команда /id показывает ID чата. Пока TELEGRAM_ALLOWED_CHAT_IDS не задана, бот реагирует только в личных чатах; чтобы ограничить доступ конкретным чатом или разрешить чат группы, укажите:

   $env:TELEGRAM_ALLOWED_CHAT_IDS = "123456789,-1001234567890"

4. Посмотрите без отправки, как формируется публикация:

   .\venv\Scripts\python.exe manage.py telegram_publish_daily --date 2026-11-06 --preview

5. Для отправки в канал сначала добавьте бота администратором с правом публикации. Затем вручную:

   .\venv\Scripts\python.exe manage.py telegram_publish_daily --chat-id -1001234567890

   Или задайте переменную TELEGRAM_CHAT_IDS (несколько ID через запятую) и используйте планировщик Windows либо cron, например ежедневно в 08:00 **Europe/Kyiv**.

## Развёртывание

- Для команд /today, /all и /date нужен **постоянно работающий отдельный процесс** python manage.py telegram_bot (long polling). Нельзя запускать несколько копий с одним токеном; при включённом webhook polling не работает.
- Для автоматической публикации достаточно запускать telegram_publish_daily по расписанию через cron/Task Scheduler с рабочими настройками Django и БД.
- Для отправки по запросу не нужен отдельный публичный webhook.
- Не храните токен в коде, приложении, переписках, логах или README. Настройте секреты на сервере/локально.
- На тестовой БД сейчас нет Edge Functions, и для этого сценария они не требуются.

## Проверки

    python manage.py test api.tests_telegram_daily

Новые файлы не меняют существующие модели, миграции или календарный API. Все исходные богослужебные тексты читаются без записи в БД.
