# Генерация нового года одной командой

Вместо предположений о повторяемости по 2026 году команда берет
точные дни празднований с azbyka.ru для выбранного года и связывает
их с отдельными уже заполненными карточками из 2026 SQLite.

  python manage.py generate_calendar_from_source --year 2028 --apply

Для 2028 используется ранее скачанный кэш 366 страниц, поэтому
повторно скачивать весь год не нужно; для следующих лет страницы
скачиваются и сохраняются автоматически. Пасха рассчитывается
по православной пасхалии и добавляется независимо от дневного списка.
Годовой календарь azbyka.ru определяет базовые постные дни.

Движок: сохраняет иконы/жития существующих карточек, отдельно
создает недостающие празднования, не смешивает двух святых с
общим названием. Формирует 365/366 дней и главную память для
отображения (не уставное старшинство церковных служб).

Защита: только локальная SQLite, неизменяемый 2026, существующие
годы не переписываются без --replace-existing, backup перед
записью, транзакция и проверка количества календарных дней.

Из C:\m\repo\molitvoslov-backend:

  .\venv\Scripts\python.exe manage.py test api.test_calendar_source_matching
  .\venv\Scripts\python.exe manage.py generate_calendar_from_source --year 2028 --apply

Для чтений дополнительно укажите --with-readings, они заполняются
после записи года из опубликованных материалов. Без флага чтения
не трогаются. --dry-run только показывает план.

Ограничения: точность зависит от полноты календаря источника;
пищевые уставные степени и все литургические сочетания служб
пока не вычисляются. При недоступности годового источника
программа не выдумывает даты и не начинает запись.
Синхронизация Supabase выполняется отдельно после проверки SQLite.
