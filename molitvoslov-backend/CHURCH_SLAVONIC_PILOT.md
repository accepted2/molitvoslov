# Церковнославянская Библия — безопасный пилот

**Ветка:** `feature/bible-csl-traditional-20261109`  
**Статус:** внутренняя тестовая реализация, **не для публикации APK** до проверки исходного корпуса и прав.

## Что реализовано

- Второй код перевода: `csl_traditional` с `language=cu` и `script_variant=church_traditional`.
- Django-команда `import_bible_church_slavonic`. Импортирует **только** Бытие (50 глав), Псалтирь (псалмы 1–150) и Матфея (28 глав) из предварительно проверенного Unicode-кандидата.
- 151-й псалом исключён из пилота: в `csl.zip` нет обычной разметки его стихов.
- Отдельный экспорт `offlineBibleCslTraditional.json` со своими ID книг и стихов.
- Выбор RU / «ЦС традиционный» на главном экране Библии и в меню самой читалки; переключение сохраняет соответствующие книгу, главу и номер стиха, если они есть в обеих версиях.
- Шрифт Ponomar включается через `metadata.language = 'traditional'` у каждого блока текста.
- Синодальная Библия `rst`, календарные ссылки, её ID и данные `offlineBible.json` **не изменяются**.

Пока в Git-ветке имеется маленький **пустой шаблон** `offlineBibleCslTraditional.json` — это необходимо для сборки Metro. Церковнославянский текст **не закоммичен**: лицензия электронной редакции не подтверждена, а полный корпус содержит дефекты.

## Подготовить пробный комплект локально

Понадобится `csl_traditional_candidate.json`, подготовленный из предоставленного `csl.zip` при аудите 9 ноября. Его нельзя заменять исходным ZIP или обычным `offlineBible.json`.

Открой PowerShell **в корне checkout**, где лежат папки `molitvoslov-backend` и `molitvoslov-app`.

1. Проверить кандидат без каких-либо записей в БД:

```powershell
cd .\molitvoslov-backend
.\venv\Scripts\python.exe manage.py import_bible_church_slavonic --input "C:\путь\к\csl_traditional_candidate.json" --check-only
```

2. Импортировать только три тестовые книги в Django:

```powershell
.\venv\Scripts\python.exe manage.py import_bible_church_slavonic --input "C:\путь\к\csl_traditional_candidate.json"
```

3. Собрать второй офлайн-пакет (указывай путь к **этому же checkout**):

```powershell
.\venv\Scripts\python.exe manage.py export_bible_content --translation csl_traditional --output "..\molitvoslov-app\src\data\offlineBibleCslTraditional.json"
```

4. Запустить тесты:

```powershell
.\venv\Scripts\python.exe manage.py test api.test_bible_church_slavonic
```

5. Пересобрать APK или запустить dev-клиент. JSON импортируется как **статический модуль**, поэтому просто синхронизация контента без пересборки приложения его не заменит.

Ожидаемый результат пилота: Бытие — 50 глав / 1533 стиха; Псалтирь — 150 псалмов / 2527 стихов; Матфей — 28 глав / 1071 стих.

## Проверки перед APK

- RU остаётся доступным без Интернета.
- В ЦС доступны Бытие, Псалтирь (1–150) и Матфей, нет пустого 151-го псалма.
- После открытия RU ↔ ЦС в одной главе номер стиха сохраняется, если такой стих имеется.
- Буквы ѣ, ѧ, ѡ, титла, ударения, надстрочные буквы видны через Ponomar без «квадратов».
- Закладки и избранное привязаны к соответствующему **ID перевода**, не к общему порядковому номеру.
- Евангельское и Апостольское чтение из календаря по-прежнему открывает Синодальную редакцию.
- Открытие без сети; повторная сборка приложения с тем же экспортом не меняет существующие ID.

1. Юридически подтвердить разрешение на распространение используемого электронного ЦС-текста.

3. Разобрать предупреждения о нумерации в остальных книгах, отдельно найти полный текст 3-й книги Ездры и 151-й псалом.
4. Сверить строки по репрезентативным главам с независимым церковнославянским изданием.
5. Только после этого разрешить импорт всех книг и создать полную офлайн-сборку.
